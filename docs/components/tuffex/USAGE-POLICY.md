# Tuffex 统一组件使用政策

> 用户已指定后续界面开发依赖 Tuffex，业务模块和主题保持低耦合。

状态：`current` · 决定日期：2026-09-13

## 范围

后续宣传主页、内部 Hub、论坛、GitHub 组织管理和其他新服务的 UI 开发及迁移，以 Tuffex 为统一基础组件库。新增或迁移到 Vue 的页面必须使用库内已有的同类组件，不另建平行的通用 UI 体系，不重复实现已经提供的基础组件。

此项是已接受的项目选择，不再沿用旧文档中“尚未选定组件库”的表述。其他项目安全、模块、贡献和可访问性规范仍然有效。

## 当前与未来

既有 web 包仍为 React，新建或迁移模块按各自 manifest 核对。此文档任务不改变应用运行框架，也不覆盖其他并行的迁移工作。不能把 Vue 组件直接导入 React 页面，也不能使用同名 React 仿制品代替真正的 Tuffex。

论坛现已另按 [ADR-0003](../../decisions/0003-adopt-tuff-forum.md) 直接采用 `app/forum` 的 Nuxt/Vue/TuffEx 原代码和上游检查；保留核心 React 页面不意味着论坛仍未迁移。该原仓仅提供浏览器演示，组件接入不代表真实认证、数据库和内部 Hub 已完成。

后续实施按产品迁移范围完成 Vue 模块、构建和依赖接入。未迁移的 React 页面保留必要维护，不为新方向扩建另一套基础组件库。实际接入需核对发行版本；当前参考源码包 0.6.0 声明 Node >=26、Vue ^3.5.27，与现有 Node 22/React 环境不同。

## 引入、封装与主题

按 [安装说明](reference/installation.md) 使用组件子路径及对应 CSS，应用壳层统一引入基础 token 样式。根入口和全量样式仅用于明确记录的迁移场景。

项目适配层只处理品牌 token、少量共用组合和应用行为，避免把所有 Props 重新包装或隐藏类型。业务组合留在所属模块，共享 UI 不反向依赖业务页面。

组件库确实没有覆盖时，先记录检索结果，再评估组合已有组件。需要新的基础原语或其他 UI 库时说明缺口和维护成本并取得明确批准，不编造 Tx 组件。

默认视觉遵循用户提供的蓝白科技、轻游戏化方向，使用官方 --tx-* token 和组件变量。立体卡片、玻璃和光效须兼顾阅读、触控、键盘、减少动效及性能，不等于真实 3D 引擎。

## 版本治理

运行版本以应用 package.json 与锁文件为准。文档固定源码提交不等于已经核实 npm latest；接入和升级要同步匹配的参考资料。普通开发和检查不自动更新上游文档。新增页面的验收必须基于真实使用的组件和工具链。
