# 论坛子域发布规范

> 子域切换涉及 DNS、TLS、代理与 Cookie，须单独授权并在发布环境验证。

状态：`current` · 更新：2026-09-12

## 前置条件

明确目标域名、源站、发布版本和回滚方案；这些值由部署者提供，不在文档保存服务器登录凭据。采用主站路径还是独立子域是一项发布决策，不能由代码目录拆分自动推导完成状态。

## 发布检查

域名解析指向获授权的目标；证书覆盖目标域名；Nginx 只有一个对应 server block，公共安全头 include 在必要作用域内生效；后端 siteHosts 与前端 sites.host 一致。Cookie Domain、GitHub OAuth 回调和论坛登录后的回跳来源必须协调。

先验证配置语法和文件访问权限，再由获授权的发布者应用配置。确认论坛入口、主题深链接、静态资源、登录/退出、上传和跨端跳转；缺失资源应返回 404，不返回错误入口 HTML。

部署与恢复的完整要求见 [DEPLOY](DEPLOY.md)。旧 deploy 目录文档仅保留本页链接，不再保存另一套操作规则。

## 凭据事件说明

本轮代码审查在旧部署文档发现一处明文服务器登录凭据，已从当前工作区移除，未使用该凭据连接任何服务器。应由所有者尽快轮换对应凭据并检查访问记录。当前文件清理不清除既有 Git 历史、缓存或已传播副本；历史处理需要单独评估和授权，不擅自改写共享历史。
