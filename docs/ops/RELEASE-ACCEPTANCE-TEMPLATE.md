# 人工验收记录模板

> 空白模板，供验收人逐字段手工填写；不是流水线自动生成的通过证明。

状态：`current` · 更新：2026-09-26

## 适用范围

字段取自 [RELEASES](../conventions/RELEASES.md)「验收记录至少包含」的要求。发版只靠打 tag：`vX.Y.Z-rc.N` 部署到预发布，验收通过后 `main` 快进到同一提交并打 `vX.Y.Z` 发正式。本模板用于「把 `main` 快进到这个提交、打正式 tag 之前」的人工试用记录（在预发布环境试用某个 rc tag 所在提交的产物）。

## 重要限制

- **Agent 不得代填任何字段**，包括“试用范围/结果”“放行结论”这类看似可以从 CI 输出推断的字段；机器验证通过（`pnpm verify`、CI 全绿）不是人工试用，也不能替代验收人签字。
- **不得把已填写的验收记录存进被验收的提交本身**：在候选 commit 之后再追加一个引用该 SHA 的验收文件会产生新提交，新提交不能冒用旧验收；记录应保存在受访问控制的审批/部署记录系统中（GitHub Deployment 审批、独立审批工单等），不进入 `main`/`stage` 的提交历史。
- 本模板本身不代表任何环境已开通、已配置人工门禁或已具备发布授权。

## 空白字段

- 验收人：
- 时间（ISO 8601，含时区）：
- 目标环境（`preview` / `production`）：
- 被验收的 rc tag（`vX.Y.Z-rc.N`）与准备发布的正式 tag（`vX.Y.Z`）：
- 完整提交 SHA（40 位小写十六进制）：
- 预发布站点显示的版本（`X.Y.Z-rc.N@<sha12>`，与 `/release.json` 的 `version` 一致）：
- 镜像 tag（三个镜像的 `<sha12>`，即部署时写入 `<栈根>/.env.<environment>` 的 `IMAGE_TAG`）：
- 被试用产物的摘要（镜像 digest，或 `/release.json` 中的组件摘要）：
- 试用范围/结果（实际点击/操作了哪些路径，观察到的真实结果，不写“预计通过”）：
- 已知问题（若无写“无”，不留空）：
- 回滚对象（若发布失败，回滚到哪个更早的正式 tag 及其 `IMAGE_TAG`）：
- 放行结论（明确“批准发布”或“不批准”，不写模糊措辞）：
- 审批记录链接（指向审批系统中该次记录的可追溯链接，不是本文件本身）：

## 使用方式

验收人复制本模板到审批记录系统中逐字段填写，不在本仓库内保存已填写的副本。填写完成、放行结论明确后，才能把 `main` 快进到被验收的提交并打正式 tag；执行人需核对该记录与实际提交、rc tag、镜像 tag 一致。正式 tag 推送后由 `deploy-production.yml`（或人工按 [DEPLOY](DEPLOY.md)）完成发布。免费版走 `scripts/deploy-manual.mjs` 部署正式环境时，`--acceptance` 要的批准评论是另发的一条新评论，整条只有「批准发布 vX.Y.Z」一行，填好的本模板不能当这条评论用；格式只以 [CICD](CICD.md#维护者机器部署免费版的退路) 第 3 条为准。
