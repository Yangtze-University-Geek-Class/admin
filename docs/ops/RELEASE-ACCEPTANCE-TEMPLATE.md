# 人工验收记录模板

> 空白模板，供验收人逐字段手工填写；不是流水线自动生成的通过证明。

状态：`current` · 更新：2026-09-13

## 适用范围

字段取自 [RELEASES](../conventions/RELEASES.md)「人工验收至少记录」的要求，用于 `release-X.Y.Z`、`prev-X.Y.Z` 里程碑 tag 以及预发布日常增量在打 tag / 执行部署之前的人工试用记录。

## 重要限制

- **Agent 不得代填任何字段**，包括“试用范围/结果”“放行结论”这类看似可以从 CI 输出推断的字段；机器验证通过（`pnpm verify`、CI 全绿、`release-policy.mjs` 输出）不是人工试用，也不能替代验收人签字。
- **不得把已填写的验收记录存进候选提交本身**，即候选提交的历史 SHA 之后再追加一个引用该 SHA 的验收文件会产生新提交，新提交不能冒用旧验收；验收记录应保存在受访问控制的审批/部署记录系统中（例如 GitHub Deployment 的审批记录、独立的审批工单），不进入仓库的发布分支或候选提交历史。
- 本模板本身不代表任何环境已开通、已配置人工门禁或已具备发布授权；`deploymentAuthorized` 在所有机器产物中恒为 `false`。

## 空白字段

- 验收人：
- 时间（ISO 8601，含时区）：
- 目标环境（`preview` / `production`）：
- 拟发布 tag（`prev-X.Y.Z` 或 `release-X.Y.Z`）：
- 完整提交 SHA（40 位小写十六进制）：
- 被试用产物的 SHA-256（对应 `release.json` 的 `manifestSha256`，或 `<artifactName>.tar.gz.sha256`）：
- 试用范围/结果（实际点击/操作了哪些路径，观察到的真实结果，不写“预计通过”）：
- 已知问题（若无写“无”，不留空）：
- 回滚对象（若发布失败，回滚到哪个已验证的历史 `releaseId` 或 `previous`）：
- 放行结论（明确“批准发布”或“不批准”，不写模糊措辞）：
- 审批记录链接（指向审批系统中该次记录的可追溯链接，不是本文件本身）：

## 使用方式

验收人复制本模板到审批记录系统中逐字段填写，不在本仓库内保存已填写的副本。填写完成、放行结论明确后，才能按 [RELEASES](../conventions/RELEASES.md) 创建对应 tag；tag 创建人需核对该记录与自己要打的 tag/commit/产物摘要一致。
