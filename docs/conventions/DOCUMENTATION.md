# 技术文档规范

> 区分当前事实、已接受决策、未实施提议和历史材料。

状态：`current` · 更新：2026-09-13

## 存放与模板

所有规范、架构、模块合同、设计决策和运维说明存放在根 `docs/`。根 README、AGENTS 和模块入口只是导航，不再建立隐藏的第二份知识库。

每篇技术文档至少包含一级标题、首个引用块摘要、状态、更新日期、适用范围、事实来源或代码位置、约束和验证方法。新增组件/模块文档说明公开接口、依赖、数据归属、异常和测试，不只画目录树。

状态仅用：`current` 当前有效；`accepted` 已接受决策；`proposed` 未实施提议；`historical` 历史记录。`accepted` 不自动表示代码已经落地，正文须列实施状态。历史文档的旧路径和数据只作历史证据。

## 事实来源

当前版本来源于 manifest、锁文件和已安装包，分清「声明范围」「锁定版本」「运行环境」「目标版本」。路线图不能写入当前技术栈。引用外部版本、标准和迁移限制时给出官方来源与核对日期；未经核对不写「最新版」。

API 来源是模块 contracts 与路由实现；权限来源是服务端检查，不以按钮是否显示为准。安全文档描述防护条件和残余风险，不使用「绝对安全」「全面通过 WCAG/ASVS」等无证据结论。

## 同步规则

变更 API -> API 文档及模块合同；数据库 -> 架构与迁移/恢复说明；环境变量 -> [公开占位模板](../ops/ENVIRONMENT.md) 与 DEPLOY；用户行为 -> USAGE；构建/验收命令 -> 根 README 与 TESTING；模块边界 -> MODULAR-DEVELOPMENT、相关模块合同与检查；文档标题/摘要/路径 -> 重新生成 INDEX。已有私有环境文件或工具限制访问的环境模板不为满足同步规则而读取，不能绕过访问限制；安全的公开配置说明只放占位值。

中文是主要规范源。英文伴随文档可以是明确标记的概要，不得保留与当前实现矛盾的旧版完整指令。规则引用优先使用相对链接；移动后验证所有相对链接，避免复制旧目录路径。

## 第三方组件参考

组件资料统一放在 docs/components 下，固定来源提交、包 manifest、许可证、转换规则和文件哈希。第三方生成资料用 `reference-snapshot` 标记，它是资料属性，不覆盖 current/accepted 项目规则。

每个库提供 AI 指南、组件/机器索引和按需查询入口；总索引不重复展开数百份生成页。原始文档和源码以不可执行文本保存；普通检查不联网，更新显式进行。实例见 [Tuffex 文档库](../components/tuffex/README.md)。

## 公开与内部文档

文件在 docs 中不代表可以公开。公开 API 使用显式白名单，只允许产品介绍和用户指南。运行路径、部署步骤、安全模型、架构盘点、审查报告和内部规范不自动发布。不得在任何文档写真实 Token、密码、会话 Cookie 或完整 .env。

## 验收

`pnpm docs:index` 更新索引；`pnpm check:docs` 检查索引、相对链接和模块入口。自动检查不证明内容语义正确，审查者仍须比对代码和声明。审查报告明确命令、结果、隔离方式以及未执行的项目。
