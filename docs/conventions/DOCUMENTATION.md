# 技术文档规范

> 区分当前事实、已接受决策、未实施提议和历史材料；`docs/` 与 `app/` 严格对齐。

状态：`current` · 更新：2026-09-23

## 存放与结构

所有规范、架构、服务合同、设计决策和运维说明存放在根 `docs/`。根 README、根 AGENTS 只作导航，不建立第二份知识库。

**目录对齐规则（硬规则）**：`app/<service>` 对应 `docs/services/<service>/README.md`（源码地图、契约、运行方式、验证命令、已知限制），模块细节放同目录子文档。新增服务必须同时补文档，缺一即视为未完成。`docs/README.md` 是 app ↔ docs ↔ 规范的三列地图；`docs/INDEX.md` 是生成物。

| 目录 | 内容 |
|---|---|
| `conventions/` | 怎么协作：分支、提交、审查、Issue/MR、发版、测试、文档 |
| `services/` | 每个 `app/<service>` 的合同与源码地图 |
| `architecture/` | 当前系统设计：拓扑、API 契约、安全模型 |
| `design/` | 界面规范与技术选型 |
| `ops/` | 部署、环境、本机预览、数据保全 |
| `decisions/` | 已接受决策（ADR） |
| `plan/` `history/` `handovers/` `reviews/` | 计划、历史材料、交接记录、交付证据 |
| `components/` | 第三方组件参考（含生成快照） |
| `public/` | 允许公开的材料 |

每篇技术文档至少包含一级标题、首个引用块摘要、状态、更新日期、适用范围、事实来源或代码位置、约束和验证方法。新增服务/模块文档说明公开接口、依赖、数据归属、异常和测试，不只画目录树。

## 状态词表

状态仅用：`current` 当前有效；`accepted` 已接受决策；`proposed` 未实施提议；`historical` 历史记录。`accepted` 不自动表示代码已经落地，正文须列实施状态。

历史文档（`history/`、`handovers/`、标注 `historical` 的 `plan/` 与 `reviews/`）里的旧路径、旧分支名、旧部署模型和数据只作历史证据：**必须显式标注历史**，不得被当作现行规范，也不得作为操作的依据。发现 current 文档与代码不一致时，先改文档再继续（见「同步规则」）。

## 事实来源

当前版本来源于 manifest、锁文件和已安装包，分清「声明范围」「锁定版本」「运行环境」「目标版本」。路线图不能写入当前技术栈。引用外部版本、标准和迁移限制时给出官方来源与核对日期；未经核对不写「最新版」。未落地的目标（例如 Postgres 迁移、统一认证）只能写在 `proposed` 或明确标注「未做」的段落里，不能写成已完成。

API 来源是模块 `contracts.ts` 与路由实现；权限来源是服务端检查，不以按钮是否显示为准。安全文档描述防护条件和残余风险，不使用「绝对安全」「全面通过 WCAG/ASVS」等无证据结论。

## 同步规则

变更 API → API 文档 + 对应 `services/*` 合同；数据库 → 架构与迁移/恢复说明；环境变量或端口 → [deploy/env/.env.production|preview](../../deploy/env) + [ENVIRONMENTS](../ops/ENVIRONMENTS.md) + [DEPLOY](../ops/DEPLOY.md)；用户行为 → [USAGE](../ops/USAGE.md)；构建/验收命令 → 根 README 与 [TESTING](TESTING.md)；服务边界或目录 → [MODULAR-DEVELOPMENT](MODULAR-DEVELOPMENT.md) 与 `docs/services/**`；文档标题/摘要/路径 → 重新生成 INDEX。私有环境文件或工具限制访问的模板不为满足同步规则而读取，不能绕过访问限制；公开配置说明只写非密值与占位符。

中文是主要规范源。英文伴随文档（`.en.md`）是明确标记的导航概要：**已有的保持同步**，不得保留与当前实现矛盾的旧版完整指令；新增规范文档不强制补 twin，只有需要英文导航时才加 `README.en.md` 之类的概要。规则引用优先使用相对链接；移动后验证所有相对链接，避免复制旧目录路径。

## 第三方组件参考

组件资料统一放在 `docs/components` 下，固定来源提交、包 manifest、许可证、转换规则和文件哈希。第三方生成资料用 `reference-snapshot` 标记，它是资料属性，不覆盖 current/accepted 项目规则。

每个库提供 AI 指南、组件/机器索引和按需查询入口；总索引不重复展开数百份生成页。原始文档和源码以不可执行文本保存；普通检查不联网，更新显式进行。实例见 [Tuffex 文档库](../components/tuffex/README.md)。

## 公开与内部文档

文件在 docs 中不代表可以公开。公开 API 使用显式白名单，只允许产品介绍和用户指南。运行路径、部署步骤、安全模型、架构盘点、审查报告和内部规范不自动发布。不得在任何文档写真实 Token、密码、会话 Cookie 或完整 `.env`；部署环境文件只允许写地址、端口、域名等可见事实，密钥字段留空。

## 验收

`pnpm docs:index` 更新索引；`pnpm check:docs` 检查索引、相对链接、服务文档与入口指针。自动检查不证明内容语义正确，审查者仍须比对代码和声明。审查报告明确命令、结果、隔离方式以及未执行的项目。
