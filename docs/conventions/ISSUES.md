# Issue 规范

> 记录可复现问题、影响范围、验收条件及安全边界。

状态：`current` · 更新：2026-09-12

缺陷 Issue 必须包含模块、观察到的行为、期望行为、最小复现步骤、版本或提交、非敏感日志和验收条件。不能以模糊的「有问题」「优化一下」代替可检查结果。

功能 Issue 说明用户场景、范围和不做什么、接口/权限/数据影响，以及如何验收。依赖升级需说明动机、官方迁移来源和回退策略，不把「最新版」当成唯一理由。

严重性按真实影响区分：阻断核心流程或数据/权限风险优先；普通功能、可访问性与维护性分别标注。未经复现的怀疑标为待确认，不以肯定语气写已证实漏洞。

关闭前链接对应改动与验证结果，不能仅因代码存在或构建成功关闭功能缺陷。安全问题私下报告，不贴 Token、真实会话、完整请求头或生产数据库。
