# Pull Request 与审查规范

> 审查代码、合同、权限、数据一致性、文档与实际验证证据。

状态：`current` · 更新：2026-09-12

## PR 内容

标题遵循 [COMMITS](COMMITS.md)。正文说明目的、关联 Issue、受影响模块、实现与取舍、验证命令/结果、兼容性与数据迁移、未验证事项和回滚方式。修复漏洞不把真实凭据或可利用的生产数据放入公开讨论。

## 审查要求

检查授权是否由服务端强制；输入是否经过运行时合同；数据库计数和状态是否原子且可重复；外部请求是否有超时和结果未知处理；共享层是否反向依赖模块；测试是否注册真实代码并隔离资源；文档是否把计划当事实。

UI 变更检查键盘、焦点、名称、错误与空状态、窄屏和导航。引入新依赖说明必要性，不因为教程使用某库就照搬整套框架。

## 门禁

根 `pnpm verify` 必须通过，相关浏览器用例通过或明确标为待验收。不得删除失败断言来取得绿色结果。无密钥、真实业务数据库、依赖缓存或无关改动。文档索引和相对链接有效。

CI 文件是否被远端执行、分支保护是否生效，需仓库管理员实际配置确认；本地提供命令不等于已有远端保护。合并与部署是独立授权操作，不由 Agent 默认执行。

## 建议模板

目的 / 关联 / 模块范围 / 关键决策 / 验证证据 / 兼容性与迁移 / 风险与未验证项 / 回滚。
