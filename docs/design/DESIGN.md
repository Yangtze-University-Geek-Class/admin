# 当前 UI 设计与可访问性规范

> 统一浅色品牌、可靠平台交互与可验证状态，区分标准要求和项目偏好。

状态：`current` · 更新：2026-10-25

## 已确定的组件体系

后续新增及迁移界面以 **Tuffex** 为统一基础组件库。规则集中在 [使用政策](../components/tuffex/USAGE-POLICY.md)，开发前先读 [AI 指南](../components/tuffex/AI-GUIDE.md)，按组件查询官方 API 和示例。下文的 React 适配器说明仅适用于尚未迁移模块的维护；实际框架与迁移状态按各模块 manifest 核实。

## 视觉基线

保留浅色校徽蓝，三端信息密度可以不同。颜色走已有 CSS 变量或语义角色，不在业务组件新增任意 hex。外部 GitHub 标签色只在受验证的适配边界处理，不扩散为组件色板。

**例外与更新（2026-09-24，2026-10-24 改版）：官网 portal 按用户指定使用下面的「YUGC OS v2」视觉语言**（桌面与窗口取自开机动画最后一帧的晴空、粉窗口与 YUGC 四色；场景页与普通页面仍是纸色 / 冰白底、钴蓝主色），不再使用 NANO · LED 点阵的藏青夜色与校徽蓝，2026-09-24 的三维书桌在 #275 删除；控制台（`app/console`）是冰白纸面 + 钴蓝、经 Tuffex 令牌表达（见下文「控制台视觉与组件规则」），论坛沿用 Tuff Forum 自带皮肤。三端各自皮肤独立，不互相继承。

间距优先 4/8px 体系，正文按场景 14–16px，合理的 20px 间距不是违规。字号使用 rem、支持放大，但不声称 rem 是唯一可访问实现。长内容优先 min-height；二维表格可在自身容器内滚动，不能为了禁止滚动截断内容。

### 首页：开机动画 → 桌面

- 今天（北京时间）没播过就先播开机动画：起步门（电脑点击或按任意键，手机点按或长按）→ BIOS 日志 → 文字散成粒子再聚成极客娘 → 闪光切到晴空 → 粉窗口弹出、YUGC 字标逐字落地 → OS 徽章、标语、boot.log 进度条 → 就绪。右上角静音、重播，右下角跳过，都是 44px 的真实按钮。就绪后在最后一帧停一下，再淡出到桌面；默认壁纸「晴空」接着最后一帧画，看不出接缝。今天播过或开了减少动态效果直接进桌面。
- 菜单栏：YUGC 四色标志、前台应用名、前往 / 窗口 / 帮助、搜索胶囊（⌘K）、时间、28px 头像；头像打开「账号资料」窗口（#280 起和其他应用一样是桌面窗口，电脑上开在右上角，手机上从底部升起）。
- 桌面左上角一列 60px 应用图标（加入我们、论坛、代码仓库排最前），单击选中、双击或回车打开，触屏单击打开；「新来的看这里」便签是窗口外框（粉色标题栏、一个关闭圆点），第一次来自动出现，看过就不再自动出现，「帮助」里能再打开。Dock 是半透明胶囊，图标下面有名字，主入口带 1/2/3 快捷键。桌面上不铺组件卡片、不写「正在招新」。
- 窗口：18px 圆角、粉色描边和标题栏，左上角三颗 22px 糖果珠，后面不垫胶囊，珠子上一直显示关闭、减号、放大的深色图标，各有 44×44 的点击区，标题居中；正文在 `--os-panel` 上，卡片 14px 圆角，链接 `--os-accent`，成功 `--os-ok`；终端窗口是 `--os-term-bg` 底和 `--os-bios-*` 文字。比赛窗口的头图和官网入口是第一期比赛官网首屏的缩小版，用官网自己的浅色而不是桌面色（#278，所有者 2026-10-24 16:38、16:57 要求比赛官网去掉暗色）：暖白点阵底、2px 墨线、实色错位投影、四团漂移的彩色柔光和流动的透视网格、贡献热力图拼出的「OSS CHALLENGE」、紫到粉到琥珀的渐变字、紫色墨线胶囊按钮。
- 壁纸：默认「晴空」是画出来的；两张极客娘图片壁纸留作可选，换壁纸的动效与预取见 [portal](../services/web/portal.md)「壁纸」。

### 手机形态

- 手机先看开机动画的手机版构图（宽度小于 768 或竖屏），再进 iPhone 主屏幕式的 YUGC OS：顶部状态栏（时间、「YUGC OS」系统设置、头像）、四列应用、Dock 是主屏幕加三个主入口。搜索是 Dock 上方的紧凑入口，也能在主屏空白处下滑打开；系统设置里能换壁纸、重播开机动画。指引按需打开，不默认展开大便签。晴空壁纸上的极客娘在开机动画层卸掉后滑到图标下面。
- 应用面板在状态栏和 Dock 之间铺开，从底部升起成页面卡片（#233），标题栏有返回主屏幕与关闭应用，不显示电脑拖动、放大按钮；返回时保留应用内容，关闭才卸载。弹层复用 shared Modal，焦点进入、Tab 循环、关闭后返回。
- 触控目标 ≥44×44 CSS px，安全区不遮控件，内容独立滚动、无页面横向溢出；断点唯一契约见 [portal](../services/web/portal.md)「手机首页与主屏幕」。

### 场景页与普通页面的色板（`--pt-*`）

- 底：纸色 `#F5F4F0`（场景页、普通页面）、冰白 `#FBFBFD`、卡片白 `#FFFFFF`。
- 文字：墨色 `#1B2140`、次级 `#5B6283`、弱化 `#646B8A`（原 `#8A91B0` 在纸色底上只有 2.8:1，已加深到 ≥4.5:1）；分隔线墨色 12% / 7%。
- 主色：钴蓝 `#3346C8`（唯一的实心主操作色，深一级 `#2638B8`，浅底 `#E6E9FB`）；琥珀 `#F5A524` 只用于提示符光标和少量点缀；状态绿 `#1FA971` 只用于成功回执；官网任何地方都不写「正在招人 / 正在招新」（2026-09-24 两次要求去掉）。
- 字体：系统中文栈（PingFang SC / 微软雅黑 / Noto Sans SC）+ 系统等宽栈（SF Mono / JetBrains Mono / Menlo）。不再自托管标题子集字体。

### 场景页

- 共用顶栏：「回到桌面」胶囊 + `~/yugc/<页>` 面包屑 + 品牌。背景是无缝影棚（地面弯成背墙）+ 柔光 + 贴地柔影。
- 桌面上只有「加入我们」进场景页；「论坛」直达论坛首页（#185），论坛场景页留给旧地址和「论坛最新」窗口里的「3D 版块」按钮。没登录时「加入我们」的信纸上只有「先注册再投递」和注册、登录两个按钮；登录后信纸底部写今天还能投几份。
- **宣传片**（#77、#103、#142；#284 起是桌面窗口）：这个浏览器第一次进「加入我们」时，桌面里自动弹出一次「宣传片」窗口（之后靠 cookie 不再自动弹，开了减少动态效果不弹），也能随时从桌面、Dock 或「加入我们」窗口里的「看宣传片」自己打开。它和其他窗口一样：能拖动、关闭、最小化再恢复（收起时暂停，恢复后接着播；关闭则停止播放），手机上是底部面板；窗口不遮住信纸。片子按 16:9 铺满窗口宽度，画面外不是深色条，而是画面本身放大模糊的颜色。画面上没有播放 / 暂停、进度条、时间、音量，也没有「跳过」按钮（2026-09-26：「只需要右上角的跳过，就是让人无感播放」，窗口化以后关闭用标题栏上的按钮）；点画面不会暂停，播完窗口自动关。浏览器不让带声音自动播时静音播放，点画面打开声音；静音也不让播，就停在封面，点画面播放。播不了或没加载出来时，窗口里写一句说明。
- **加入我们**：信封从正上方偏后落下、停在画面正中（信箱在右边，从右上方进场会穿过信箱）；封舌翻开，三折信纸抽出；镜头推近，信纸边飞边展开，平贴屏幕落在正中（宽至多 640px），最后一帧与 DOM 表单严丝合缝后换成可填写的信纸——纸色、横格线、校徽、下划线式输入框；左侧说明在信纸落位前淡出，信封缩小平躺在信纸下方。提交成功后：信纸在原位两道折痕折好 → 飞回信封塞进去 → 封舌合上 → 火漆落下并压扁一下 → 信封沿弧线飞到信箱正前方、路上转正放平并缩到比投信口窄，再沿信箱法线直直推进投信口，小旗弹起 → 左侧出现回执（编号、时间、服务端原文）。缓动以三次缓入缓出与五次缓出为主，只在火漆与小旗上用一点回弹。
  - 信封材质（2026-09-24 反馈质感太差、有穿模后重做）：象牙色纸面 + 共用的纸纹凹凸贴图（细颗粒与短纤维），四边有折口暗影，封舌合上时在口袋上投一道软影；边上是钴蓝与琥珀相间的航空信斜纹；背面（地址面）有红色邮编框、带齿孔的校徽邮票、邮戳和手写的「长江大学 极客班 收」；内衬是深钴蓝底的细线六边形。底板有 0.01 厚、口袋有厚度、左右与下边有窄边墙，侧面看是纸袋而不是两张面片。火漆是不规则外形、带倒角的一团蜡，校徽同时做凹凸贴图压在顶面。信纸背面受光且带一点自发光，翻过来背光时仍是纸色。
  - 层次（信封局部 z）：底板 -0.011..-0.001 │ 信纸 0.002..0.0052 │ 口袋 0.008..0.012 │ 封舌 0.013 │ 火漆落在封舌表面。封舌翻过一半后铰链挪到底板后面，信纸抽出与塞回都在封舌前面。
- **论坛**：五个版块是五个立体对话气泡，围成一圈缓慢自转、可拖动；悬停浮起并冒出「正在输入」三点，点击推近进入版块；中间校徽圆台 = 论坛首页。左侧主按钮「进入论坛首页」一直可见，下面是等价的版块列表（图标 + 名称 + 说明），也是键盘与窄屏入口。

### 普通页面（文档、意见箱、邀请加入）

纸色底 + 淡图纸线；顶部一条白色系统栏（品牌 + 路径 + 文档/意见箱/论坛 + 「加入我们」主按钮）；内容放在窗口式卡片里（红黄绿三点 + 路径 + 状态徽标）；表单输入框浅底、1.5px 边框、聚焦钴蓝边框 + 4px 焦点环；错误用红色图标 + 文字，不只靠颜色。不放吉祥物插画，不用藏青页头胶囊。

### 必须 / 禁止

- 必须：只用令牌；触控目标 ≥44px（桌面菜单栏等系统级小控件除外）；焦点可见；看不见的层置 `inert`；长文本单行省略、grid 子项 `min-width: 0`，任何分辨率下不溢出卡片；1280×800、1440×900、1920×1080、390×844 下桌面图标、便签与 Dock 互不遮挡；`prefers-reduced-motion` 下不播开机动画，场景直接给最终状态。
- 性能：开机动画是 Canvas 2D，粒子数按核心数和像素比收紧；3D 场景（加入我们、论坛）像素比起步 min(DPR, 2)，由调速器按帧间隔自动降档（2 → 1.5 → 1.25，同一会话只降不升），按需渲染。背景模糊只用在窗口、菜单栏、Dock 这些面板上（SPEC §1 的 `--os-panel`），全屏层和弹层遮罩不用 `backdrop-filter`（细则见 [portal 合同](../services/web/portal.md)「性能预算」）。
- 禁止：界面里出现 emoji 和装饰性 unicode 箭头/符号（↵ ↗ ✓ ▶ ← → ● ♡ ♪ ✧ 等，一律换 Remix 线性图标或矢量图形；允许 ⌘ · … ×）；把快照数据写成实时数据；学期、年份、成员数等会过期或编造的数字；把该皮肤套到管理员端或论坛。

### 已知不足

- 对比度、屏幕阅读器、iOS Safari 真机与中低端安卓未做专项测试。`--os-ink-soft`（`#5b7fb5`）在白底上约 4.1:1，低于普通文本 4.5:1，用作次要文字时要放在大字或非关键信息上，或另行加深。
- 开机动画的帧率和窗口背景模糊在中低端设备上的开销还没有在真实浏览器里测过。

## 控制台视觉与组件规则（app/console）

2026-09-24（#13）起，极客班控制台是 Vue 3 + Tuffex 包，所有控件都用 Tuffex 组件，不再有浏览器原生下拉框、复选框。实现与令牌清单见 [console 合同](../services/console/README.md)。这是 Operate 界面：先求扫读、一致、平静。

- **只经令牌换肤**：`app/console/src/styles/theme.css` 只覆盖 Tuffex 官方的 `--tx-*` 与 `--tx-bui-*` 令牌——主色钴蓝 `#3346C8`（`--tx-color-primary`，派生色按官方做法 color-mix）、藏青墨色、冷灰边框与填充、页面底 `#F4F6FC`；语义色取服务端 `roles.ts` 的色调（白底 ≥5:1）。组件不写颜色值；自写 CSS 只管版式和页面底（4% 钴蓝图纸网格，面板纯白）。
- **称号徽章**：TxTag（soft）+ 称号图标 + 称号名字；名字、图标、色调都是数据（控制台「称号」里改，经 `/api/console/catalogue` 下发），默认值是提督 violet、舰长 amber、队长随部门色、部门舰员 slate、舰员 sky、领航员 jade、乘客 slate（2026-09-25 定的星舰命名，见 [SECURITY](../architecture/SECURITY.md)）。队长与部门舰员的徽章写「部门名 · 称号名」并用部门图标。
- **字体**：一套无衬线（系统中文栈）；等宽只给 GitHub 登录名、编号、提交号和代码。
- **组件对应**：导航 TxSidebarNav（≤900px 收进 TxDrawer）；列表 TxDataTable（窄屏在自己的容器里横向滚动）；分区 TxTabs；筛选 TxFilterChips；表单 TxForm/TxFormItem + TxInput/TxTextarea/TxSelect/TxCheckbox/TxRadio/TxSwitch/TxNumberInput；对话框 TxModal；反馈 TxToastHost、TxAlert；状态 TxSkeleton、TxEmptyState、TxErrorState、TxPermissionState；指标 TxStatCard。Tuffex 里有的就不自己写。
- **状态**：加载、空、失败（带重试和 `HTTP · 机器码 · request id`）、缺能力（写明缺哪项，被 GitHub 组织角色挡住时说明原因）、未登录分开。危险操作先确认，初始焦点在「取消」。
- **文案**：短、具体、从用户这边说。标签说名字，按钮说动作，空/错状态说发生了什么、下一步做什么。不写口号，不用「赋能 / 打造 / 一站式 / 沉浸式」，不用 emoji 和装饰性箭头符号；图标只用 Tuffex/Carbon。
- **成员与权限**：顶层「成员 / 称号 / 部门 / 权限树」四个文字页签（「称号」只给能管理称号的人）。「成员」左边是有宽松点击目标的全部成员、各部门和没有部门（带人数），右边是当前分组概况与按「称号层级 → 部门顺序 → 登录名」排序的名单；双栏限高，名单独立滚动，不随成员数量无限延伸；称号来源与撤销操作按人展开，默认保持单行扫读；窄屏时分组横排。「部门」只有组织 owner 能看到编辑与删除，服务端也核对 owner，不以按钮显隐代替授权。「称号」与「部门」按条目呈现基础能力与部门能力，不把解释机制的长文案当主视觉。「权限树」用只读能力列表和详情，视角从真实接口动态生成；状态筛选只有结果不同时才出现，切换视角后重置筛选，搜索只影响能力列表；错误时不显示旧结论，窄屏选择后能到达详情并返回原节点。

## 既有 React 模块的过渡期交互原语

Modal 使用 dialog.showModal，提供名称、适当描述、关闭、焦点进入/返回和背景 inert；组件内显式处理首尾 Tab/Shift+Tab 循环，避免焦点进入浏览器界面或背景。破坏性操作用 alertdialog，初始焦点取消；不全局监听 Enter 直接确认。确认排队，卸载取消未完成请求。

Select 是唯一项目选择器适配器，内部使用平台选择语义；撤销历史上无条件禁止 native select 的要求。业务页面仍统一使用适配器，不创建第二套交互。NumberInput 保留编辑中间态，失焦规范化。

图片预览、反馈和管理弹层复用 Modal。验证码统一生命周期，错误有明确恢复路径。不因教程使用组件库就迁移全部技术栈。

## 无障碍目标

以 WCAG 2.2 AA 为验收目标，不宣称已达标。普通文本至少 4.5:1，大文本至少 3:1；关键非文本控件按适用条款验证。焦点可见，键盘能完成主流程，关闭后返回触发元素。错误不能仅靠颜色。

触控目标优先 44px，WCAG 24px 下限具有间距等例外；图标视觉尺寸不等于热区。支持文字放大和 prefers-reduced-motion。二维内容按标准例外处理，不机械要求所有表格压缩到 320px。

## 状态、表单和导航

加载、空、失败、权限不足、成功分开。网络错误不冒充空数据，重要失败持续可见。适当使用 role=status/alert，不因轻提示抢焦点。控件须有准确名称或关联 label，密码输入支持管理器和粘贴。

分页 URL、query key 和 API 一致；跨端用 externalUrl，同端用 Router。小屏幕不能因侧栏隐藏而失去导航。Markdown 只走统一净化入口，复制/预览支持键盘。

## 当前选型与验收

既有 `app/web` 包（官网）使用 React 18、Tailwind 3 和自有适配器；后续 UI 已由用户指定采用 Tuffex（Vue 3）。控制台已迁到 `app/console`（Vue 3 + Tuffex 0.9.1），论坛是 `app/forum`；官网仍是 React。按各服务的实际框架、依赖和发布版本验证接入，不再引入平行基础 UI 体系。

组件测试验证取消、焦点目标、异步参数、错误；浏览器验证 Tab/Esc、背景模态性、移动导航和分页。对比度、屏幕阅读器、多浏览器及放大测试单独记录，不能从源码推断整个产品通过 WCAG。
