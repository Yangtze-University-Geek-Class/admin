# 当前 UI 设计与可访问性规范

> 统一浅色品牌、可靠平台交互与可验证状态，区分标准要求和项目偏好。

状态：`current` · 更新：2026-09-13

## 已确定的组件体系

后续新增及迁移界面以 **Tuffex** 为统一基础组件库。规则集中在 [使用政策](../components/tuffex/USAGE-POLICY.md)，开发前先读 [AI 指南](../components/tuffex/AI-GUIDE.md)，按组件查询官方 API 和示例。下文的 React 适配器说明仅适用于尚未迁移模块的维护；实际框架与迁移状态按各模块 manifest 核实。

## 视觉基线

保留浅色校徽蓝，三端信息密度可以不同。颜色走已有 CSS 变量或语义角色，不在业务组件新增任意 hex。外部 GitHub 标签色只在受验证的适配边界处理，不扩散为组件色板。

**例外与更新（2026-09-23）：官网 portal 已按用户指定改用下面的「MiMo 风格基线」**，`app/web/sites/portal` 的新页面不再使用校徽蓝；管理员端仍是浅色校徽蓝，论坛沿用 Tuff Forum 自带皮肤。三端各自皮肤独立，不互相继承。

间距优先 4/8px 体系，正文按场景 14–16px，合理的 20px 间距不是违规。字号使用 rem、支持放大，但不声称 rem 是唯一可访问实现。长内容优先 min-height；二维表格可在自身容器内滚动，不能为了禁止滚动截断内容。

## 官网视觉语言：MiMo 风格基线（portal）

用户 2026-09-23 指定参照 `https://mimo.mi.com/`。下表的数值来自当天对参照站**实测计算样式**（不是印象），实现落在 `app/web/sites/portal/theme.css` 的 `.mimo-page` 作用域内。改这里的值等于改规范：先改文档，再改令牌。

### 色板（实测参考值 → 本项目令牌）

| 用途 | 参照站实测 | 本项目令牌 | 说明 |
|---|---|---|---|
| 页面底 | `#FFFFFF` / 暖白 `#FCFAF8` | `--mimo-canvas` | 大面积留白，不用彩色底 |
| 面板 / 卡片 | `#F6F3EE`、`#F0EBE5`、`#F4F3F1` | `--mimo-surface` / `--mimo-surface-strong` | 暖米色，靠明度差分层 |
| 沙色分隔 | `#E8E1D8`、`#E7E0D6` | `--mimo-sand` | 纹理/分隔 |
| 主文本 | `#000000` | `--mimo-ink` | 标题与实心按钮 |
| 次文本 | 中灰 | `--mimo-ink-soft` / `--mimo-muted` | 只用两档，不再分更多灰阶 |
| 强调 | 鼠尾草绿 `rgb(82 110 62)`（10% 用于底） | `--mimo-accent` / `--mimo-accent-soft` | 仅用于强调行、状态与焦点环 |
| 边框 | `#E6E1DA` 系 | `--mimo-line` / `--mimo-line-strong` | 1px 细线，不叠阴影 |

### 形状与层级

- 圆角：小控件 8px、输入 12px、卡片 16–20px、大画布卡 28px、按钮胶囊 999px。
- 阴影只有两级：常态卡片 `0 1px 2px / 0 14px 34px`（4–5% 黑），抬升态略强；**不用彩色发光阴影**。
- 节奏：区块间距 80–96px，卡片内边距 36px，窄屏 20–24px。

### 排版

- 字体：系统中文栈（PingFang SC / 苹方 优先），不加载品牌字体、不用装饰性字重。
- 展示标题：`clamp(38px, 6vw, 68px)`、字重 400、行高 1.1、字距 -0.03em；两行结构，第二行可换强调色。
- 区块标题 22–28px / 600；正文 16px / 1.7；辅助信息 12.5–13.5px。
- 参照站的中文标题**不是粗体**，加粗反而失真；靠字号与留白建立层级。

### 组件基线

- 公告条：黑底白字单行，右侧一个下划线链接。
- 页头：白底 88% 透明 + `backdrop-filter: blur(18px)`，1px 底边；左品牌（36px 图标 + 主副标题），右侧最多三个入口，主操作为黑实心胶囊。
- 主视觉：居中；eyebrow（12px、字距 .22em）→ 两行大标题 → 引导段（≤640px）→ 胶囊按钮组（一屏最多一个黑实心）→ 大圆角画布卡。
- 画布卡：鼠尾草渐变底 + 角色/主视觉 + 左上角状态标记 + 底部居中白色胶囊说明；卡片下方是标题 + 一句说明。
- 表单卡：暖米色底、28px 圆角；输入框白底、1px 边框、聚焦时 accent 边框 + 4px accent-soft 焦点环；错误红字并置 `aria-invalid`。
- 页脚：黑底，品牌 + 文字链接组 + 分隔线版权。

### 必须 / 禁止

- 必须：只用令牌（业务组件不写任意 hex）；触控目标 ≥44px；焦点可见；错误不只靠颜色；`prefers-reduced-motion` 下关闭动效；文案与配置分离（首页文案在 `app.config.json > portal.hero`，入口在 `portal.navigation`）。
- 禁止：引入第二套组件库或第二份令牌；复制参照站的文案、图标、图片或品牌元素；把该皮肤套到管理员端或论坛；大面积 accent 底色、渐变文字、彩色发光阴影。

### 已实现范围与已知不足

- 已实现：官网首页（`pages/Landing.tsx`）、投递简历服务（`pages/Apply.tsx`）、共享页头页脚（`components/SiteHeader.tsx`、`SiteFooter.tsx`）。
- 已知不足（后续迭代方向）：主视觉画布卡的构图偏"图库式"、窄屏信息密度偏松、缺少与参照站同等水准的章节节奏与滚动编排；讨论与验收证据见交接文档。

## 既有 React 模块的过渡期交互原语

Modal 使用 dialog.showModal，提供名称、适当描述、关闭、焦点进入/返回和背景 inert；组件内显式处理首尾 Tab/Shift+Tab 循环，避免焦点进入浏览器界面或背景。破坏性操作用 alertdialog，初始焦点取消；不全局监听 Enter 直接确认。确认排队，卸载取消未完成请求。

Select 是唯一项目选择器适配器，内部使用平台选择语义；撤销历史上无条件禁止 native select 的要求。业务页面仍统一使用适配器，不创建第二套交互。NumberInput 保留编辑中间态，失焦规范化。

图片预览、反馈和管理弹层复用 Modal。验证码统一生命周期，错误有明确恢复路径。不因教程使用组件库就迁移全部技术栈。

## 无障碍目标

以 WCAG 2.2 AA 为验收目标，不宣称已达标。普通文本至少 4.5:1，大文本至少 3:1；关键非文本控件按适用条款验证。焦点可见，键盘能完成主流程，关闭后返回触发元素。错误不能仅靠颜色。

触控目标优先 44px，WCAG 24px 下限具有间距等例外；图标视觉尺寸不等于热区。支持文字放大和 prefers-reduced-motion。二维内容按标准例外处理，不机械要求所有表格压缩到 320px。

## 状态、表单和导航

加载、空、失败、权限不足、成功分开。网络错误不冒充空数据，重要失败持续可见。适当使用 role=status/alert，不因轻提示抢焦点。控件须有准确名称或关联 label，密码输入支持管理器和粘贴。

分页 URL、query key 和 API 一致；跨端用 externalUrl，同端用 Router。小屏幕不能因侧栏隐藏而失去导航。Markdown 只走统一净化入口，复制/预览支持键盘。

## 当前选型与验收

既有 `app/web` 包使用 React 18、Tailwind 3 和自有适配器；后续 UI 已由用户指定采用 Tuffex（Vue 3）。文档库落地不代表各业务模块已迁移。按各服务的实际框架、依赖和发布版本验证接入，不再引入平行基础 UI 体系。

组件测试验证取消、焦点目标、异步参数、错误；浏览器验证 Tab/Esc、背景模态性、移动导航和分页。对比度、屏幕阅读器、多浏览器及放大测试单独记录，不能从源码推断整个产品通过 WCAG。
