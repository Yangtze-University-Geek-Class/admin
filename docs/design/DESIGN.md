# 当前 UI 设计与可访问性规范

> 统一浅色品牌、可靠平台交互与可验证状态，区分标准要求和项目偏好。

状态：`current` · 更新：2026-09-24

## 已确定的组件体系

后续新增及迁移界面以 **Tuffex** 为统一基础组件库。规则集中在 [使用政策](../components/tuffex/USAGE-POLICY.md)，开发前先读 [AI 指南](../components/tuffex/AI-GUIDE.md)，按组件查询官方 API 和示例。下文的 React 适配器说明仅适用于尚未迁移模块的维护；实际框架与迁移状态按各模块 manifest 核实。

## 视觉基线

保留浅色校徽蓝，三端信息密度可以不同。颜色走已有 CSS 变量或语义角色，不在业务组件新增任意 hex。外部 GitHub 标签色只在受验证的适配边界处理，不扩散为组件色板。

**例外与更新（2026-09-24）：官网 portal 按用户指定使用下面的「浅色书桌 × YUGC OS」视觉语言**（纸色 / 冰白底、钴蓝主色、少量琥珀点缀），不再使用 NANO · LED 点阵的藏青夜色与校徽蓝；控制台（`app/console`）是冰白纸面 + 钴蓝、经 Tuffex 令牌表达（见下文「控制台视觉与组件规则」），论坛沿用 Tuff Forum 自带皮肤。三端各自皮肤独立，不互相继承。

间距优先 4/8px 体系，正文按场景 14–16px，合理的 20px 间距不是违规。字号使用 rem、支持放大，但不声称 rem 是唯一可访问实现。长内容优先 min-height；二维表格可在自身容器内滚动，不能为了禁止滚动截断内容。

## 官网视觉语言：浅色书桌 × YUGC OS（portal）

用户 2026-09-24 确认的方向（源自已批准的独立原型 `desk-prototype`）：首屏是一张浅色书桌上的笔记本电脑，点电脑开机进入「YUGC OS」——极客班的内部系统桌面；三个主入口「加入我们 / 论坛 / GitHub」各有一个 3D 小场景。要求：简洁大气、浅色、没有大块空白、没有溢出，长期不写学期或年份（只说「我们正在招人」）。此前的 NANO · 代码窗口 × LED 点阵方向（藏青夜色、滚动舞台、挥手帧序列、入口卡立绘）已整体退役，代码与素材已删除。实现与模块地图见 [portal 合同](../services/web/portal.md)。改这里的值等于改规范：先改文档，再改 `app/web/sites/portal/styles/portal.css` 的令牌。

### 色板与字体

- 底：纸色 `#F5F4F0`（书桌、场景页）、冰白 `#FBFBFD`（系统桌面、开机画面）、卡片白 `#FFFFFF`。
- 文字：墨色 `#1B2140`、次级 `#5B6283`、弱化 `#8A91B0`；分隔线墨色 12% / 7%。
- 主色：钴蓝 `#3346C8`（唯一的实心主操作色，深一级 `#2638B8`，浅底 `#E6E9FB`）；琥珀 `#F5A524` 只用于提示符光标、铅笔和少量点缀；状态绿 `#1FA971` 只用于「招人中」与成功回执。
- 字体：系统中文栈（PingFang SC / 微软雅黑 / Noto Sans SC）+ 系统等宽栈（SF Mono / JetBrains Mono / Menlo）。不再自托管标题子集字体。加载动画的手写签名用系统手写体（Snell Roundhand / Apple Chancery / Segoe Script）。

### 首页：加载 → 书桌 → 开机 → 桌面

- **加载动画**（首次进入）：纸色底 + 点阵 + 一道扫描线；超大描边字 YUGC 按**真实进度**从下往上灌满钴蓝；校徽的六片花瓣逐片点亮；手写「Geek Class」随进度写出；底部等宽日志与三位数百分比；就绪后幕布上下合拢。进度只来自真实步骤（three 分包、环境贴图、场景搭建、校徽、着色器编译、第一帧），同一会话第一次至少约 2.1s、之后 0.5s，减少动态效果时跳过。
- **书桌**（three.js）：木纹桌面、铝壳笔记本（屏幕上是开机按钮）、马克杯与热气、绿植、NANO 的小机器人、钴蓝笔记本与铅笔、便签、墙上校徽海报。左侧文案 + 「打开电脑」按钮 + 「跳过动画」；悬停物体有等宽小提示；点屏幕开机，点机器人会跳、点杯子冒热气、点植物会抖。
- **开机画面**：校徽花瓣飞入拼合、外环描出、`YUGC OS` 字样、五行 `[ OK ]` 日志与进度条，NANO 从右下探出打招呼（全站唯一一处吉祥物立绘）；任意键或点击跳过。
- **YUGC OS 桌面**：顶部菜单栏（系统菜单 / 前台应用 / 前往 / 窗口 / 帮助 / 搜索 ⌘K / 时钟）；下方是**铺满屏幕的仪表盘网格**——左列欢迎区（提示符、两行标题、说明、三个主入口按钮带 1/2/3 快捷键、文档/意见箱/控制台小链接），中间与右侧依次是论坛最新（快照）、招新状态（钴蓝实色卡：我们正在招人 + 三步 + 加入我们）、公开仓库（语言色点 + 最近推送）、日历与时钟、组织架构（班长、四个部门卡、成员与领航员称号）、终端预览；右侧一列桌面图标；底部 Dock。所有卡片可点：打开窗口（关于、组织架构、论坛最新、终端）、进入 3D 场景或跨站。
- 背景：几团极淡的径向渐变（钴蓝、暖杏、冰蓝）+ 96px/24px 两级图纸线（边缘渐隐）+ 右下角大号描边校徽水印（钴蓝 5.5%）。

### 三个场景页

- 共用顶栏：「回到桌面」胶囊（直接回到系统桌面，不重播书桌）+ `~/yugc/<页>` 面包屑 + 品牌。背景是无缝影棚（地面弯成背墙）+ 柔光 + 贴地柔影。
- **加入我们**：信封从右上飞入、停在画面正中；封舌翻开，三折信纸抽出；镜头推近，信纸边飞边展开，平贴屏幕落在正中（宽至多 640px），最后一帧与 DOM 表单严丝合缝后换成可填写的信纸——纸色、横格线、校徽、下划线式输入框；左侧说明在信纸落位前淡出，信封缩小平躺在信纸下方。提交成功后：信纸在原位两道折痕折好 → 飞回信封塞进去 → 封舌合上 → 火漆落下并压扁一下 → 信封沿弧线飞进一侧的信箱，小旗弹起 → 左侧出现回执（编号、时间、服务端原文）。缓动以三次缓入缓出与五次缓出为主，只在火漆与小旗上用一点回弹。
- **论坛**：五个版块是五个立体对话气泡，围成一圈缓慢自转、可拖动；悬停浮起并冒出「正在输入」三点，点击推近进入版块；中间校徽圆台 = 论坛首页。左侧主按钮「进入论坛首页」一直可见，下面是等价的版块列表（图标 + 名称 + 说明），也是键盘与窄屏入口。
- **GitHub**：53 周 × 7 天的方块地形从地面依次升起成天际线，公开仓库名是立在高处的楼牌，前方一台小终端逐字敲出 `gh org view`；色阶与高度标「示意」。打开 GitHub 时方块像瀑布一样依次熄灭。

### 普通页面（文档、意见箱、邀请加入）

纸色底 + 淡图纸线；顶部一条白色系统栏（品牌 + 路径 + 文档/意见箱/论坛 + 「加入我们」主按钮）；内容放在窗口式卡片里（红黄绿三点 + 路径 + 状态徽标）；表单输入框浅底、1.5px 边框、聚焦钴蓝边框 + 4px 焦点环；错误用红色图标 + 文字，不只靠颜色。不放吉祥物插画，不用藏青页头胶囊。

### 必须 / 禁止

- 必须：只用令牌；触控目标 ≥44px（桌面菜单栏等系统级小控件除外）；焦点可见；看不见的层置 `inert`；长文本单行省略、grid 子项 `min-width: 0`，列表按卡片高度截断，任何分辨率下不溢出卡片；1280×800、1440×900、1920×1080 下仪表盘铺满、无大块空白；`prefers-reduced-motion` 下跳过加载动画与镜头飞行，场景直接给最终状态。
- 性能：像素比上限 1.5，阴影 1024 且按需刷新，按需渲染，系统桌面盖住画布时 3D 循环停止，大面积层不用 `backdrop-filter`（细则见 [portal 合同](../services/web/portal.md)「性能预算」）。
- 禁止：界面里出现 emoji 和装饰性 unicode 箭头/符号（↵ ↗ ✓ ▶ ← → ● 等，一律换 Remix 线性图标；允许 ⌘ · … ×）；把快照或示意数据写成实时数据；学期、年份、成员数等会过期或编造的数字；深色整页；把该皮肤套到管理员端或论坛。

### 已知不足

- 对比度、屏幕阅读器、iOS Safari 真机与中低端安卓未做专项测试。
- 3D 场景是程序化几何，没有外部模型；首屏 three 分包约 0.5MB（gzip 约 130KB）。

## 控制台视觉与组件规则（app/console）

2026-09-24（#13）起，极客班控制台是 Vue 3 + Tuffex 包，所有控件都用 Tuffex 组件，不再有浏览器原生下拉框、复选框。实现与令牌清单见 [console 合同](../services/console/README.md)。这是 Operate 界面：先求扫读、一致、平静。

- **只经令牌换肤**：`app/console/src/styles/theme.css` 只覆盖 Tuffex 官方的 `--tx-*` 与 `--tx-bui-*` 令牌——主色钴蓝 `#3346C8`（`--tx-color-primary`，派生色按官方做法 color-mix）、藏青墨色、冷灰边框与填充、页面底 `#F4F6FC`；语义色取服务端 `roles.ts` 的色调（白底 ≥5:1）。组件不写颜色值；自写 CSS 只管版式和页面底（4% 钴蓝图纸网格，面板纯白）。
- **称号徽章**：TxTag（soft）+ 称号图标 + 中文称号，颜色来自 `/api/console/catalogue` 的 `tones`：班长 amber、部门负责人随部门色、部门干事 slate、极客班成员 sky、领航员 violet、访客 slate。名单里部门另起一列，徽章只写「部门负责人」「部门干事」。
- **字体**：一套无衬线（系统中文栈）；等宽只给 GitHub 登录名、编号、提交号和代码。
- **组件对应**：导航 TxSidebarNav（≤900px 收进 TxDrawer）；列表 TxDataTable（窄屏在自己的容器里横向滚动）；分区 TxTabs；筛选 TxFilterChips；表单 TxForm/TxFormItem + TxInput/TxTextarea/TxSelect/TxCheckbox/TxRadio/TxSwitch/TxNumberInput；对话框 TxModal；反馈 TxToastHost、TxAlert；状态 TxSkeleton、TxEmptyState、TxErrorState、TxPermissionState；指标 TxStatCard。Tuffex 里有的就不自己写。
- **状态**：加载、空、失败（带重试和 `HTTP · 机器码 · request id`）、缺能力（写明缺哪项，被 GitHub 组织角色挡住时说明原因）、未登录分开。危险操作先确认，初始焦点在「取消」。
- **文案**：短、具体、从用户这边说。标签说名字，按钮说动作，空/错状态说发生了什么、下一步做什么。不写口号，不用「赋能 / 打造 / 一站式 / 沉浸式」，不用 emoji 和装饰性箭头符号；图标只用 Tuffex/Carbon。
- **成员与权限**：顶层「成员 / 部门与权限包」两个分区；成员按「全部 / 班长 / 部门负责人 / 部门干事 / 极客班成员 / 领航员」分页签，每页一张按「称号 rank → 部门顺序 → 登录名」排好的表，没有页内搜索。

## 既有 React 模块的过渡期交互原语

Modal 使用 dialog.showModal，提供名称、适当描述、关闭、焦点进入/返回和背景 inert；组件内显式处理首尾 Tab/Shift+Tab 循环，避免焦点进入浏览器界面或背景。破坏性操作用 alertdialog，初始焦点取消；不全局监听 Enter 直接确认。确认排队，卸载取消未完成请求。

Select 是唯一项目选择器适配器，内部使用平台选择语义；撤销历史上无条件禁止 native select 的要求。业务页面仍统一使用适配器，不创建第二套交互。NumberInput 保留编辑中间态，失焦规范化。

图片预览、反馈和管理弹层复用 Modal。验证码统一生命周期，错误有明确恢复路径。不因教程使用组件库就迁移全部技术栈。

## 无障碍目标

以 WCAG 2.2 AA 为验收目标，不宣称已达标。普通文本至少 4.5:1，大文本至少 3:1；关键非文本控件按适用条款验证。焦点可见，键盘能完成主流程，关闭后返回触发元素。错误不能仅靠颜色。

触控目标优先 44px，WCAG 24px 下限具有间距等例外；图标视觉尺寸不等于热区。支持文字放大和 prefers-reduced-motion。二维内容按标准例外处理，不机械要求所有表格压缩到 320px。

## 状态、表单和导航

加载、空、失败、权限不足、成功分开。网络错误不冒充空数据，重要失败持续可见。适当使用 role=status/alert，不因轻提示抢焦点。控件须有准确名称或关联 label，密码输入支持管理器和粘贴。

分页 URL、query key 和 API 一致；跨端用 externalUrl，同端用 Router。小屏幕不能因侧栏隐藏而失去导航。Markdown 只走统一净化入口，复制/预览支持键盘。

## 当前选型与验收

既有 `app/web` 包（官网）使用 React 18、Tailwind 3 和自有适配器；后续 UI 已由用户指定采用 Tuffex（Vue 3）。控制台已迁到 `app/console`（Vue 3 + Tuffex 0.6.0），论坛是 `app/forum`；官网仍是 React。按各服务的实际框架、依赖和发布版本验证接入，不再引入平行基础 UI 体系。

组件测试验证取消、焦点目标、异步参数、错误；浏览器验证 Tab/Esc、背景模态性、移动导航和分页。对比度、屏幕阅读器、多浏览器及放大测试单独记录，不能从源码推断整个产品通过 WCAG。

依据：https://www.w3.org/TR/WCAG22/ ，https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/ 。视觉数值和组件取舍是项目决策，不冒充标准强制条款。
